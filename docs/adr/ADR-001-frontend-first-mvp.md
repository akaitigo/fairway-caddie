# ADR-001: フロントエンド先行MVP + ローカルストレージ永続化

## Status
Accepted

## Context
fairway-caddie はクラブ別飛距離分布の可視化とコース攻略の確率的最適化がコアバリュー。
MVP では以下の選択肢がある:

1. バックエンド (Go API + PostgreSQL) を先に構築し、フロントエンドを接続
2. フロントエンド (React + D3.js) を先行し、ローカルストレージで永続化

## Decision
**フロントエンド先行MVP + ローカルストレージ永続化**を採用する。

- データモデルは TypeScript の型定義として設計
- 永続化は `localStorage` の CRUD 操作で実装
- 座標は WGS84 (EPSG:4326) で統一し、将来の PostGIS 移行に備える
- 推薦エンジンのインターフェースを抽象化し、将来の Python ML 移行に備える

## Consequences

### Positive
- 可視化（コアバリュー）の検証が最速で可能
- バックエンド不要のためデプロイが簡単（静的ホスティング）
- ユーザーフィードバックを早期に取得可能

### Negative
- localStorage の容量制限（約5MB）により大量データには不向き
- デバイス間のデータ同期不可（MVP スコープ外）
- ストレージ層の差し替え作業が Phase 1 で発生

### Risks
- localStorage のデータ消失リスク（ブラウザクリア時）
  - 緩和策: エクスポート/インポート機能を Phase 1 で検討
- 型定義とバックエンド API スキーマの乖離
  - 緩和策: Zod等のランタイムバリデーション導入を検討
